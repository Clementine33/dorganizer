## 1. 目标与范围

将当前 libraries 的浏览和管理能力移入“工作集”。用户选择媒体库后直接进入工作台，在概览浏览目录、选择转换范围，并在同一个工作台内管理文件和审阅转换计划。

### S1 本次必须交付

- 媒体库选择、管理、扫描、概览文件夹列表。
- 概览与转换共用文件树及文件管理能力。
- 每个媒体库、每种操作只保留最后一条处理记录。
- 每条记录只保留当前计划及其执行结果。
- 成员内部的单项重命名、单项移动、批量软删除。

### S2 本次不实现

未来的新媒体库产品形态、`/rename`、跨成员移动、成员根目录管理、拖拽、应用内回收站、旧数据迁移、自动 VACUUM。

“工作集”暂时作为产品入口名称；代码中的现有 workset 复用为处理记录，不做全仓库命名替换。不为未来任务建立占位路由或通用计划解释框架。

## 2. 页面与导航

### N1 路由

| 路由 | 内容 |
|---|---|
| `/worksets` | 媒体库选择 |
| `/worksets/libraries/:libraryId` | 概览与成员 |
| `/worksets/libraries/:libraryId/files?folder=…` | 概览中的文件树 |
| `/worksets/libraries/:libraryId/conversion` | 当前转换记录 |
| `/worksets/libraries/:libraryId/conversion/members/:memberId/files` | 转换成员文件树 |

转换设置、成员设置、批量编辑和执行结果继续作为转换下的子路由。根地址进入 `/worksets`。原全局“媒体库”入口隐藏，本期不维护旧页面链接兼容。

### N2 工作台行为

- 选择媒体库后进入概览，不自动创建处理记录。
- 概览、转换及文件树共享一个 `WorkbenchShell`。
- 树视图占用主区域，不放入窄详情栏。
- 返回目标由路由明确决定，不依赖浏览器历史猜测。
- 同一工作台内返回列表，保留勾选、筛选和滚动位置；刷新浏览器后不恢复临时勾选。
- 切换媒体库清空原库的临时选择；未应用的转换编辑沿用离开保护。
- 当前记录被另一页面替换时，旧成员链接显示“处理记录已更新”，提供返回转换入口，不跳到另一个成员。

### N3 概览与成员

展示媒体库全部直接子文件夹，包括空目录和仅含非音频文件的目录。

- 排除库根下的应用回收目录 `Delete/`。
- 媒体库根目录中的散落文件不作为成员。
- 文件夹是否含音频是状态信息，不决定是否允许浏览和管理。
- 文件夹入口使用库相对路径定位，不依赖重扫后会变化的 `folderId`。
- 提供已有的媒体库管理、扫描、取消扫描入口。

## 3. 转换记录与计划生命周期

### R1 创建与替换

概览勾选后点击“进入转换”：

1. 明确展示本次有效范围及无音频、将跳过的目录。
2. 全部无音频时不创建记录。
3. 有旧记录时确认替换，说明其设置、计划和执行结果将删除。
4. 后端创建新记录成功后，在同一事务中替换并清理旧记录。
5. 创建失败保留旧记录及当前选择。
6. 创建成功直接进入转换设置与成员界面，不再要求命名。

新记录使用现有默认设置与策略槽，不复制旧记录配置。生成计划和执行仍是后续独立动作，进入转换不会修改媒体文件。

沿用有效成员数量上限 500；超过上限明确阻止创建，不静默截断。成员范围由后端校验，前端提示不能替代后端校验；选择与提交之间目录状态变化时必须反馈实际范围，不静默扩大用户确认的范围。

### R2 唯一归属

每个 `(library_id, operation_type)` 最多一条当前记录。当前仅允许 `conversion`。

- 直接点击侧栏“转换”进入该记录。
- 没有记录时引导返回概览选择文件夹。
- 记录创建仅初始化请求的操作，取消为所有注册任务同时初始化的行为。
- 旧记录处于排队、生成或执行中时禁止替换。
- 并发替换必须比较调用方见到的当前记录 ID；已发生替换时返回冲突，不能覆盖另一页面的新记录。

### R3 仅保留当前计划

- 生成期间保留上一份成功计划，可只读查看，不允许执行。
- 新计划成功发布后，事务性切换当前计划并清理旧计划、旧执行结果及其关联明细。
- 生成失败、取消或中断，不替换旧计划。
- 删除历史版本入口，不再支持 `?revision=` 浏览旧计划。
- 保留冻结快照、输入有效性校验、草稿版本检查及每份计划最多执行一次的约束。
- 当前计划已执行后，不得通过再次点击执行重跑同一计划。

技术性会话及幂等凭据可以按现有保留期存在；它们不作为用户可浏览的历史计划。仅隐藏历史界面但继续永久保留旧计划或执行明细，不满足本节。

### R4 重试语义

- 同一次创建请求响应丢失后，使用同一幂等键重试，返回已创建的当前记录。
- 相同键、不同请求内容返回冲突。
- 已被后续记录替换的旧创建请求不得恢复旧记录或再次替换当前记录。
- 被清理计划的旧生成/执行请求不得生成额外计划或再次写入文件。
- 失效的记录和计划链接返回明确的不存在或已替换状态。

## 4. 共用文件树

### T1 模块职责与身份

共用文件夹模块接收媒体库 ID、成员根目录的库相对路径，以及调用页面决定的返回地址。它负责当前文件读取、刷新、选择、文件管理及操作结果反馈，不读取转换草稿或解释转换计划。

转换页面通过稳定 `memberId` 解析目录身份；概览直接使用库相对路径。后端统一验证目录属于媒体库且是允许浏览的成员根。

复用现有树渲染和选择逻辑。未来 `/rename` 可以复用当前文件模块，它自己的计划审阅届时单独设计。

### T2 当前文件

- 展示音频、非音频文件和空子目录。
- 每次进入此页自动刷新该成员目录；缓存可以先展示。
- 刷新完成前禁止文件修改；失败时保留旧视图并明确标注未刷新。
- 提供手动刷新。
- 符号链接不递归，第一版不提供对链接及穿过链接路径的修改操作。
- 目录不存在时显示缺失状态，不自动创建或关联同名替代目录。

### T3 计划审阅

仅转换成员入口提供“当前文件 / 计划审阅”：

- 有计划时默认审阅，无计划时默认当前文件。
- 按计划冻结数据构建文件树，展示保留、删除、转换及预计新增输出和原因。
- 计划树展示计划涉及的文件，不承诺包含未参与转换的全部非音频文件。
- 明确标识待生成文件，不能将其当作磁盘现有文件操作。
- 计划审阅只读；直接文件管理必须切换到当前文件。
- 输入已变化时保留原计划展示，同时提示需重新生成。

不得使用最新扫描树冒充计划的冻结视图。

## 5. 文件管理与失败行为

### F1 操作范围

允许修改成员内部的文件和子目录，不允许修改成员根目录本身。

| 操作 | 第一版行为 |
|---|---|
| 重命名 | 单项修改名称，不接受路径作为新名称 |
| 移动 | 单项移入同一成员内已有目录，通过目录选择器操作 |
| 软删除 | 多选文件或子目录，确认后移入库级 `Delete/` |

不提供覆盖同名目标、跨成员移动、新建目录或跨文件系统复制后删除。

软删除保留原相对层级，回收目标重名时生成不冲突名称；结果展示实际回收路径，支持复制。用户通过系统文件管理器恢复。

### F2 批量软删除

- 父目录及其子项同时选中时，只保留父目录操作，避免重复处理。
- 按界面确定的顺序逐项执行。
- 首项失败后停止后续操作。
- 返回已成功、失败及未处理项；不自动撤销已成功项。
- 重试仅针对重新核实后的未完成项目。

### F3 后端校验

所有写操作由后端独立验证：

- 路径属于指定成员，拒绝绝对路径、越界路径及符号链接逃逸。
- 拒绝修改成员根、将目录移入自身或其后代。
- 操作前检查源是否存在、类型是否符合、目标是否冲突。
- 同名拒绝覆盖，包括目标在操作期间出现的情况。
- 使用适合目标平台的目录约束与不覆盖操作，不能只靠字符串前缀或“先检查、再无条件覆盖”。
- 权限不足、文件占用、目录变化等失败给出可理解的信息。

外部程序仍可能修改文件；应用互斥不等于锁住整个操作系统。不得以这一限制省略路径约束或冲突保护。

### F4 修改后的同步

磁盘操作完成后刷新受影响库存、概览统计、树缓存及相关记录状态。

- 音频路径或其他转换输入变化，按现有音频指纹判定计划失效。
- 仅修改图片、文本或空目录，不强制转换重新规划。
- 库根存在重叠时，相关库存不能继续作为已确认的新数据使用；执行前仍须重新扫描校验。
- 磁盘修改成功但刷新失败时，明确显示“文件已修改，刷新失败”，禁止继续基于旧树修改。
- 网络中断导致结果未知时，不自动重试写操作；提示刷新核实。
- 刷新失败不回滚已经发生的文件修改。

## 6. 并发、接口与存储

### C1 全局文件管理互斥

增加后端统一准入控制：

- 任意扫描、排队/进行中的生成或执行存在时，拒绝手动文件管理。
- 手动文件管理期间，拒绝启动新的扫描、生成或执行。
- 多个手动文件管理请求串行准入，忙时明确返回，不建立隐形队列。
- 检查与登记必须原子完成，不能仅在前端禁用按钮。
- 不改变原有扫描、生成、执行彼此之间的并发规则。
- 文件操作后的内部刷新属于同一次操作，不重新申请导致自锁。
- 媒体库根变更和删除不得与文件管理交错。

### I1 HTTP 与类型变化

继续复用现有 libraries、worksets 和 conversion 接口，增加以下最小能力。实现者需将具体 HTTP 方法、路径、请求/响应类型和错误码同步到 `docs/api.md`，下表行为是硬约束。

| 能力 | Interface 变化 |
|---|---|
| 目录列表 | 返回全部直接子目录及音频数量，提供稳定的相对路径身份 |
| 文件树读取与刷新 | 按媒体库 ID、成员相对路径读取；显式刷新接口重新扫描该成员 |
| 文件管理 | 接受成员相对路径及 rename/move/soft-delete 操作，返回逐项结果与刷新状态 |
| 创建当前记录 | 增加操作类型及预期旧记录 ID，按相对路径接收选择范围，返回创建结果与跳过目录 |
| 当前记录查询 | 按媒体库和操作获取零或一条记录 |
| 计划读取 | 只支持当前计划，不再提供用户历史列表能力 |

文件管理的 Interface 不包含转换类型、草稿或 revision。错误须区分忙碌、路径非法、源缺失、目标冲突、部分成功和刷新失败。

### D1 存储

- 用数据库唯一约束保证每库每种操作只有一条记录。
- 显式清理旧计划与执行明细，不能依赖当前不完整的级联关系。
- 新记录发布与旧记录清理、新计划发布与旧计划清理分别在事务中完成。
- 保留当前计划的冻结数据，不另建一套执行快照。
- 本期不增加归档表、回收站记录系统或定期数据库压缩。

### L1 媒体库管理

- 删除媒体库前确认连同设置、计划和执行结果删除。
- 有活动任务时拒绝删除。
- 删除只影响应用记录，不动媒体文件及 `Delete/`。
- 存在处理记录时允许改名，禁止更换根目录。
- 无记录时可修改根目录，清理旧库存并要求重新扫描。

### D2 新数据库与兼容

使用新数据库验证，不迁移、不清空原数据库。旧数据库遇到不兼容结构时明确拒绝启动并提示使用新数据目录，不能自动重置。测试使用隔离数据与临时媒体，不修改用户真实媒体。

## 7. 验收标准

以下各项均须提供实现位置和验证证据。无法运行的检查必须标记未验证及具体原因，不能用编译成功代替运行时验证。

### A1 导航和浏览

- 从工作集选择媒体库进入概览，全局旧媒体库入口不可见。
- 空目录、非音频目录可见，库级 `Delete/` 不进入成员列表。
- 概览和转换均能进入同一文件树能力，返回后列表状态保留。
- 重扫产生新的扫描 ID 后，概览和成员树链接仍正确。
- 桌面及窄屏维持一个工作台、一个交互实例，键盘操作和焦点返回可用。

### A2 记录和计划

- 无音频目录明确跳过；全无音频不创建；超过 500 个有效成员不截断。
- 替换失败不丢旧记录，成功后旧记录和关联计划不残留。
- 并发替换只允许一个成功；重试不重复创建；旧请求不恢复已替换内容。
- 新计划失败保留旧计划，成功后旧计划及旧执行结果清理。
- 输入变化、草稿变化、活动任务和重复执行仍正确阻止执行。
- 删除媒体库及根目录变更遵循 L1；旧数据库按 D2 明确拒绝而非被清空。

### A3 文件管理

- 文件、空目录及非空子目录可按范围重命名、移动、软删除。
- 越界、符号链接、目标冲突、自身/后代移动、成员根修改均被拒绝。
- 批量父子选择去重，遇错停止，部分成功结果准确。
- 删除回收路径正确且不覆盖已有回收内容。
- 文件修改与扫描、生成、执行的竞争由后端阻止。
- 刷新失败和请求结果未知不会导致自动重复写入。
- 修改音频使相关计划失效；修改非音频不误判转换输入变化。
- 重叠库根与跨平台路径没有绕过范围保护或提供虚假的库存新鲜状态。

### A4 验证与完成门槛

使用现有 Go、Vue 和端到端测试设施，测试公开行为。遵守仓库 Go 外部测试包、手写 fake 和并发测试规则，不为此引入新测试框架。

完成 Go lint/test、Web typecheck/test/build，关键浏览器流程，以及包含路径与文件操作的 Windows 验证。Windows 交叉编译只能作为编译证据，不能声称完成 Windows 文件系统行为测试。

所有功能验收项、文档契约、测试和未验证限制都已逐项核对后，才能报告交付完成。不能以“主流程可用”替代安全、重试、失败恢复和存储清理验收。

## 8. 实施顺序与强约束

1. 调整记录唯一归属和当前计划生命周期，补齐事务与重试测试。
2. 将 libraries 浏览能力接入新工作台路由，放宽目录列表并修正稳定定位。
3. 接入共用当前文件树及转换计划树。
4. 实现文件管理与全局准入，再开放写操作按钮。
5. 完成端到端验证，更新领域文档与 HTTP 契约，记录替代旧领域决策的 ADR。

实现默认值：保留 500 成员上限；只支持现有 `conversion`；不增加新依赖；旧页面路由不兼容；暂不增加历史、自动 VACUUM 或未来任务占位。

实现者可在上述行为内选择最小代码组织和具体接口命名，必须在文档中落实接口契约。涉及范围、数据删除时机、执行安全、并发承诺、兼容政策的变化必须反馈用户，不能静默降级或用 TODO 代替交付。

保留工作区中与本任务无关的已有改动。禁止自动删除原数据库、真实媒体，禁止未经请求提交、推送或发布。

## 9. 导航身份调整：短路由与目录标识（2026-09-20）

本节取代 §2 N1 的路由表，以及 N3 与 §4 T1 中“用库相对路径定位”的表述；其余章节不变。本节描述目标行为，不代表已经实现；理由与取舍见 [ADR 0008](adr/0008-short-routes-and-directory-identity.md)。

### N1′ 路由

| 页面 | 路由 |
|---|---|
| 媒体库选择 | `/worksets` |
| 概览 | `/worksets/:L` |
| 概览文件树 | `/worksets/:L/f/:D` |
| 当前转换 | `/worksets/:L/conversion` |
| 转换成员详情 | `/worksets/:L/conversion/:M` |
| 转换成员文件树 | `/worksets/:L/conversion/:M/files` |
| 转换成员编辑 | `/worksets/:L/conversion/:M/edit` |
| 公共设置 | `/worksets/:L/conversion/settings` |
| 批量编辑 | `/worksets/:L/conversion/batch-edit` |
| 执行结果 | `/worksets/:L/conversion/execution` |

`L` 为现有媒体库 ID，`M` 为现有成员 ID，`D` 为新的目录标识；不额外缩短或替换现有数据库 ID。静态页面与成员路由显式区分。继续复用现有工作台与子路由载体，缩短地址不改变组件挂载、返回目标与列表状态保留方式。所有跳转使用命名路由与参数，不再拼接路径字符串。旧长路由直接停用，不做兼容重定向：显示“不存在页面”并提供返回工作集入口，不猜测目标。

### N3′ 目录标识

后端生成 `dir_id`：对 `[版本标记, 媒体库 ID, 规范化库根身份, 库存中的准确相对路径]` 做 JSON 编码，标准库 SHA-256 取前 128 位，输出 32 位小写十六进制；不做大小写折叠、Unicode 归一化或重复 URL 解码。同一库根与相对路径下，重扫、重启保持不变；成员根被外部改名或媒体库换根，旧标识失效；同一路径后来重新出现时标识仍相同。标识不是访问凭据。

### I1′ 接口变化

- 目录列表与转换成员响应增加 `dir_id`，由后端统一计算。
- 树读取改为 `GET /libraries/:id/tree?dir=:dirId`，树刷新改为 `POST /libraries/:id/tree/refresh?dir=:dirId`；响应提供解析后的 `dir_id`、`member_path` 与原有树数据。
- 后端从该媒体库库存的直接子目录解析标识，再执行原有目录存在性、回收目录、符号链接与范围校验。不认识的标识返回明确的目录不存在；非法格式拒绝；碰撞时拒绝解析，不取第一个匹配。
- 旧 `folder` 定位参数停止支持。文件操作所需的名称与相对路径继续放在 JSON 请求体中。
- 解析只查询直接子目录身份，不为解析标识计算全库音频统计；本期不增加缓存或索引表。

### 自动隐藏规则

- 搜索词从 `q` 参数移入工作台临时状态：页面内返回保留，刷新及复制链接不恢复。
- URL 仅允许各页面明确支持的参数，例如文件树的 `view=current|plan`、转换列表的有限英文筛选值；统一在路由入口按页面白名单清理多余参数，使用 `replace`，不增加历史记录，不反复重定向。
- 移除不支持的 fragment；内部导航不透传整个 `query`。
- 页面面包屑显示真实名称，链接使用 ID。

### 缓存

查询缓存以媒体库、库根身份与 `dir_id` 区分；概览与转换访问同一目录时复用当前文件缓存。转换计划审阅仍使用冻结数据，不依赖实时目录是否存在。

### A5 本次验收

- 中文、日文、韩文、空格、`%`、`#`、`?`、emoji 和不同 Unicode 字节序列的目录可定位。
- 页面与树请求 URL 无文件名；JSON 中路径保持原样。
- 重扫、重启后链接稳定；外部改名、换根后的旧链接明确失效。
- 深链接刷新、新标签页、前进后退与固定返回入口可用。
- 概览与转换缓存一致；处理记录替换后旧成员不串到新记录。
- 搜索词不进入地址；白名单清理不产生循环或额外历史。
- 旧页面路由及旧 `folder` 请求停止支持。
- 原有文件管理的鉴权、目录范围、互斥和计划有效性不回退。
