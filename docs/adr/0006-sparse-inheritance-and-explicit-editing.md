# 0006 稀疏继承与显式编辑

Date: 2026-09-22

Status: Accepted

早期模型把完整的公共策略复制进每个成员的覆盖里：改一次公共设置，要么批量重写所有成员，要么让已有覆盖悄悄落后于新公共值。我们需要「继承」成为一等概念——公共值改变时，没有显式覆盖的成员自动跟随——同时又不允许编辑在用户不知情时发生。

## 1 稀疏继承与覆盖组

- 四个原子覆盖组：`mode`、`classifier_tags`、`matched`、`unmatched`。
- 缺失的覆盖意味着继承当前公共值；存在的覆盖整体替换该组，不做递归合并。**显式空值与等于公共值的显式值都算覆盖**：它们与继承是不同的配置关系。
- 删除键恢复继承；空标签数组是显式值（表示「清空该组的标签」），不是缺失。
- 排除（excluded）只改变该成员在这次操作中的参与，保留其覆盖与继承关系。
- 生效设置由公共值与成员覆盖解析而来，并附带每组值的来源（公共或成员）。

## 2 显式编辑入口

- 公共设置、批量编辑与成员编辑是三个显式入口；**仅勾选不决定编辑目标**。
- 批量编辑冻结其成员列表，只更新被有意改动的组；其他组与其继承关系保持不变。恢复继承与设置一个值是两件不同的事，界面必须能分别表达。
- 草稿持久化在版本守卫下原子替换整个稀疏文档；结构合法但不完整的草稿可以保存，生成时才完整校验参与成员的有效设置；全部排除的草稿可以保存但不能生成。
- 草稿的脏判定比较语义哈希（含继承关系），不是元数据计数器，也不只是生效值；重新选回已保存的值不算脏。

## 3 策略槽与分类标签库

- 三个全局策略槽是可复用模板，不是草稿里的活引用：应用一个槽会复制它的策略，之后修改模板不影响已保存的草稿或计划。
- 分类标签库同理提供可复用的字面标签，不重写已保存的草稿与冻结的计划。

## 替代方案权衡

- 拒绝「把公共值复制进每个成员的完整覆盖」：公共值一改就要批量重写，或让覆盖悄悄落后；稀疏继承把「跟随」变成默认。
- 拒绝「等于公共值的覆盖不存」：那会让「显式设为与公共相同」与「继承」无法区分，用户在切换公共值时的预期随之丢失。
- 拒绝递归合并目标（matched/unmatched）组：部分合并让「这一组当前是什么」需要重放历史才能回答。
- 拒绝「选中即编辑目标」：选择是批量动作与浏览的输入，把它当编辑目标会让无意的一次勾选改变某个成员的配置。
- 拒绝在批量编辑里重写未改动的组：那会把「我改了 A」变成「我确认了 B」，让继承关系在用户不知情时消失。
- 拒绝草稿里的活引用策略槽：草稿必须是自洽快照，否则模板一改，历史计划与已保存草稿的含义都会变。
