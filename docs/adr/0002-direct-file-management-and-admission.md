# 0002 直接文件管理与全局准入互斥

Date: 2026-09-22

Status: Accepted

在受控文件管理之前，唯一的磁盘写入路径是执行计划的当前版本，用户想改一个文件名也要走完整转换流程。目录整理需要重命名、移动与批量软删除，因此开放第二条写入路径：它不伪装成计划，但必须有自己的路径保护、并发控制与结果反馈契约。

## 1 受控的写入路径

- 范围：成员内部的单项重命名、单项移动（移入同一成员内已有目录）、批量软删除。不操作成员根、不跨成员移动、不覆盖同名目标、不新建目录、不做跨文件系统复制后删除。
- 请求形状即契约：重命名与移动各只接受一项，只有软删除是批量。未知操作、不可用的成员、非法路径、空项与多项都拒绝**整个请求**（`OPERATION_DENIED` 或 `REQUEST_REFUSED`），此时成员从未成为作用域，因此没有部分执行。
- 批量软删除：按界面确定的顺序逐项执行；父目录与其子项同时选中时只保留父目录（子项报 `COVERED_BY_PARENT`），重复项只处理一次；首项失败即停止（其后报 `not_attempted`）；不自动回滚已成功项；逐项返回成功、失败、跳过与未处理。
- 软删除保留原相对层级：移入库级 `<库根>/Delete/<相对路径>`，即在成员目录旁边而绝不在成员内部，回收内容因此不会重新进入成员库存。目标重名不覆盖，生成 `<stem>.N<ext>`；返回实际回收路径，供用户用系统文件管理器恢复。
- 后端独立验证每一项：路径属于该成员（拒绝绝对路径、越界路径与符号链接逃逸）、操作前检查源存在与类型、目标不冲突（包括目标在操作期间出现）、拒绝把目录移入自身或其后代、使用目标平台的不覆盖 rename。
- 修改后同步：磁盘操作完成后刷新受影响的库存（成员目录与回收目录）。文件已修改但刷新失败时，两个事实分别报告，禁止继续基于旧树修改；请求结果未知时提示刷新核实，绝不自动重试写操作。刷新失败不回滚已经发生的文件修改。
- 外部程序仍可能修改文件：应用内互斥不等于锁住整个操作系统，但不得以这一限制省略路径约束或冲突保护。

## 2 全局准入互斥

- 进程级准入槽位：任意扫描、排队或运行中的生成、执行存在时，拒绝手动文件管理；手动文件管理期间也拒绝启动这些任务；库根变更与删除占用同一槽位。
- 检查与登记在后端原子完成，忙时明确拒绝（`BUSY`），不建立隐形队列；多个手动文件管理请求串行准入。
- 文件操作后的内部刷新属于同一次受保护操作，不重新申请准入，因此不会自锁。
- 该决定不改变原有扫描、生成、执行彼此之间的并发规则，也不改变执行会话内部的编码池、提交顺序与停止行为（0007）。
- 选择全局互斥而非路径级协调：多个媒体库根可能重叠，现成的精确根路径检查不足以保护通用文件写入；接受「其他媒体库忙时暂时不能手动整理」的代价，避免引入需要维护生命周期与重叠判定的锁管理器。

## 替代方案权衡

- 拒绝路径级锁管理器：它需要在重叠根、符号链接与跨库操作上定义锁语义，收益在常见工作流中用不到；只有实际使用证明全局互斥不可接受时再评估。
- 拒绝只在前端禁用按钮：绕过前端就绕过了保护，检查与登记必须在后端原子完成。
- 拒绝把文件管理伪装成计划：它不是计划，没有草稿或 revision；但它与计划执行共享同一份路径保护与准入。
- 拒绝跨成员移动与覆盖同名目标：跨成员移动会同时改动两条记录的库存与计划有效性；覆盖同名会破坏「永不覆盖」这一可恢复性前提。
- 拒绝「先检查、再无条件覆盖」的实现：字符串前缀检查与先查后写都不是保护，使用目标平台的不覆盖原语。
