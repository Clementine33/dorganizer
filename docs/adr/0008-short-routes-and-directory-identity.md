# 8. 短路由与目录标识：地址不含名称

Date: 2026-09-20

Status: Accepted; implemented.

工作台的页面地址把目录的库相对路径放进查询串（`/worksets/libraries/:libraryId/files?folder=…`），树请求同样如此：地址因此携带目录名、分隔符与查询文本，层级也比需要更深。我们决定缩短路由，用后端计算的目录标识 `dir_id` 取代 URL 中的相对路径，并让 URL 只保留各页面明确支持的少量参数。

详细行为与验收并入工作集工作台 Spec v1 §9（该 spec 是本次工作的任务控制文档，保存在工作区但不入库）；HTTP 契约见 [docs/api.md](../api.md)。本文记录长期决定及其理由，不改变 [ADR 0007](0007-library-workbench-and-current-operation-record.md) 关于处理记录、当前计划、共用文件模块与准入互斥的决定。

## Context

ADR 0007 §3 选择成员相对路径作为浏览与文件管理的身份，这在数据层是耐久且必要的：重扫不改变路径，扫描时重建的 folder UUID 不能再承担长期导航身份。但把它直接放进地址带来三个问题。

第一，地址与树请求携带目录名（含空格、`%`、`#`、`?`、emoji 等），复制链接、书签与日志都会扩散用户目录名。第二，路径每多一层 `/libraries`，与产品入口只有“工作集”一层的事实不符。第三，页面地址一旦承载任意用户输入（搜索词），地址的含义就不再稳定，也无法用白名单约束。

用户确定：页面地址与 HTTP 请求 URL 均不含目录名、文件名或搜索词，同时刷新、复制链接与浏览器前进后退继续可用；名称与路径仍可显示在页面与 JSON 数据中；此改造不属于加密或权限控制。

## Decision

### 1. 页面路由只带 ID 与目录标识

| 页面 | 路由 |
|---|---|
| 媒体库选择 | `/worksets` |
| 概览 | `/worksets/:L` |
| 概览文件树 | `/worksets/:L/f/:D` |
| 当前转换 | `/worksets/:L/conversion` |
| 转换成员详情 | `/worksets/:L/conversion/:M` |
| 转换成员文件树 | `/worksets/:L/conversion/:M/files` |
| 转换成员编辑 | `/worksets/:L/conversion/:M/edit` |
| 公共设置 | `/worksets/:L/conversion/settings` |
| 批量编辑 | `/worksets/:L/conversion/batch-edit` |
| 执行结果 | `/worksets/:L/conversion/execution` |

`L` 是现有媒体库 ID，`M` 是现有成员 ID，`D` 是新的目录标识；不额外缩短或替换现有数据库 ID。静态页面与成员路由显式区分。跳转统一使用命名路由与参数，删除散落的路径字符串拼接，不引入通用路由框架。

旧长路由直接停用，不做兼容重定向：命中旧地址显示“不存在页面”并提供返回工作集的入口，不猜测目标。

### 2. 目录标识由固定输入派生

后端生成 `dir_id`：对 `[版本标记, 媒体库 ID, 规范化库根身份, 库存中的准确相对路径]` 做 JSON 编码，用标准库 SHA-256 取前 128 位，输出 32 位小写十六进制。输入不做大小写折叠、Unicode 归一化或重复 URL 解码；解析时严格校验格式。

不新增映射表，不用随扫描重建的 folder UUID，也不用 Base64 之类的可逆名称编码冒充隐藏。标识不是访问凭据：现有鉴权与路径安全校验继续执行；文件操作所需的名称与相对路径仍放在 JSON 请求体中。

### 3. 标识绑定路径，不绑定文件系统实体

同一库根与相对路径下，重扫与重启保持同一标识；成员根被外部改名或媒体库换根，旧标识失效，解析为明确的“目录不存在”；同一路径后来重新出现时标识仍然相同。

### 4. 树接口按标识读取

`GET /libraries/:id/tree?dir=:dirId` 与 `POST /libraries/:id/tree/refresh?dir=:dirId`；响应提供解析后的 `dir_id`、`member_path` 与原有树数据，目录列表与转换成员响应增加 `dir_id`。后端从该媒体库库存的直接子目录解析标识，再执行原有的存在性、回收目录、符号链接与范围校验：不认识的标识返回明确的目录不存在，非法格式拒绝，碰撞时拒绝解析而不是取第一个匹配。旧 `folder` 定位参数停止支持。

解析只查询直接子目录身份，不为解析标识计算全库音频统计；本期不增加缓存或索引表。

### 5. URL 只保留页面明确支持的参数

搜索词从地址移到工作台临时状态：页面内返回保留，刷新与复制链接不恢复。URL 只允许各页面白名单内的参数（例如文件树的 `view=current|plan`、转换列表的有限英文筛选值），在路由入口用 `replace` 清理多余参数与不支持的 fragment，不产生额外历史，也不反复重定向；内部导航不透传整个 query。面包屑的祖先层级显示真实名称、链接使用 ID；当前页显示该页自身的名称，宽屏面包屑、中档抽屉标题与窄屏钻取说同一句（`route.meta.title`），文件夹名称留在页面正文里而不在面包屑中重复。

### 6. 缓存按媒体库、库根身份与标识区分

概览与转换访问同一目录时复用同一份当前文件缓存；计划审阅继续使用冻结数据，不依赖实时目录是否存在。

## Superseded decisions

- ADR 0007 §3 与 spec §2 N1、N3、§4 T1 中“URL 与入口使用库相对路径定位”的表述，由本文的 `dir_id` 与短路由取代。成员相对路径仍是数据层身份与文件操作请求体中的地址；member ID 仍用于转换成员路由。
- 其余决定不变：每库每种操作一条当前记录、只保留当前计划、共用文件模块与任务独立解释计划、直接文件管理的受控写入、全局准入互斥、库存新鲜度与计划有效性分开判断。
- 本次不迁移数据库、不改媒体文件、不引入依赖：`dir_id` 是计算值，不落库。

## Consequences and rejected alternatives

- 链接可以安全地复制与固定；代价是外部改名或换根后旧链接失效。这是绑定路径的必然结果：宁可明确提示，也不自动打开另一个对象。目录消失、库根变化与处理记录替换分别给出各自的提示。
- 拒绝“新增映射表”：它引入需要维护、清理与失效的状态，而标识可由路径确定性地重算。
- 拒绝用 folder UUID 承担导航身份：它在重扫时重建。
- 拒绝 Base64 或转义名称充当隐藏：它是可逆的，不构成“地址不含名称”。
- 拒绝保留旧长路由的重定向：两套地址都要维护，且旧地址本身携带名称。
- 接受地址里 id 的现有长度（媒体库 36 位 UUID，成员 30 位 `m-<纳秒>-<随机>`，成员页地址约 94 字符），不为此改路由或改 id 生成。缩短只有三条路，各有代价：改铸短 id 会让新旧长度并存并牵动数据生成；用成员序号（1–500）最省字节，但记录被替换后同一序号指向另一个文件夹，旧链接会静默打开另一个对象 —— 正是本文要避免的，成员 id 的长度买的就是“记录已替换”可被识别；前缀截断在成员 id 上天然歧义（同一记录内铸出的 id 纳秒前导位相同），而碰撞只能拒绝，对链接而言等于失效。
- 接受接口的最小变化：目录列表与转换成员各多一个字段，树接口换参数并回传解析结果，旧参数不再支持。已有鉴权、目录范围、并发互斥与计划有效性校验不回退。
