# 0001 媒体库即工作台：处理记录与当前计划

Date: 2026-09-22

Status: Accepted

早期模型要求先创建命名的「工作集」（固定成员集合加永久 revision 历史），普通浏览也要先绕过这一层；概览跳到独立的 libraries 文件树，返回后失去上下文。现在让媒体库本身成为工作台：浏览、整理与转换都在库内完成，每种操作只保留一条当前记录与一份当前计划，去除命名集合与历史管理的复杂度。

## 1 媒体库拥有工作台

- 产品入口保留「工作集」，选中媒体库即进入它的工作台：概览列出库根的全部直接子目录，**包括空目录与仅含非音频文件的目录**；库级回收目录 `Delete/` 不是成员。
- 概览、转换与文件树共用同一个工作台外壳与同一份工作台导航。
- 每个 `(library_id, operation_type)` 至多一条当前记录，由数据库唯一约束保证；当前只有 `conversion`。创建记录只初始化所请求的操作。
- 目录是否含音频是状态，不是浏览或管理的门槛。转换仍只处理用户明确选择的音频输入，不顺带扩展库根散落文件或成员根管理。

## 2 处理记录与当前计划的生命周期

- 用户明确选择范围后才创建记录；有旧记录时先确认替换，创建成功才在同一事务中替换并清理旧记录（成员、操作、草稿、当前计划与其执行结果）。创建失败保留旧记录与当前选择。
- 排队或运行中的生成、执行存在时禁止替换；并发替换比较调用方见到的当前记录 ID，已发生替换时返回冲突而不是覆盖。
- 每个操作至多一个排队或运行中的生成会话；生成期间该操作的草稿被锁定，草稿保存与生成请求都会在会话结束前被拒绝，冻结输入因此不会与草稿替换相竞。
- 幂等：同一请求（同一幂等键与同一请求内容）重试返回既有结果，同一幂等键用于不同请求返回冲突；幂等窗口与保留期对齐。
- 计划：生成期间保留上一份成功计划（只读、不可执行）；新计划成功发布才在同一事务中切换并清理被替代的计划与其执行结果；失败、取消或中断不替换。记录只保留当前计划，不提供历史版本入口，也不在数据库永久保留历史载荷。
- 保留的约束：当前计划的不可变快照、草稿并发版本、输入有效性校验、每份计划最多执行一次。简化的是历史保留，不是执行安全。
- 执行接受当前计划的完整版本，可选按 `folder_paths` 限定本次运行的成员；请求里的路径必须是记录成员，否则拒绝（`FOLDER_NOT_IN_RECORD`）而不是静默跳过。校验版本、当前计划身份、草稿哈希、无活动生成、输入有效、无阻塞组件。
- 会话在写盘前通过扫描器刷新其输入，比对的是磁盘现状而不是上次扫描的结果；刷新无法完成则会话失败，不在未核实的事实上继续。
- 保存不生成，生成不执行，执行是独立的显式步骤；一份计划最多运行一次。
- 规划状态、输入有效性与结果事实是彼此独立的轴：改变、未满足目标、阻塞与未变化是并列的计数，不用一个排他状态标签推导它们。

## 3 共用当前文件与计划审阅

- 概览与转换共用同一个文件夹模块：负责当前文件读取、刷新、选择、文件管理与结果反馈，不读转换草稿、不解释计划。它有两个真实调用方，因此不实现成转换专属能力。
- 概览的地址由目录标识 `dir_id` 承担，转换入口先由稳定 `member_id` 解析目录（`rel_path` 仍是数据层身份与文件操作的地址）。扫描时重建的 folder ID 不承担长期导航身份。
- 计划审阅由转换侧从冻结数据构建：保留、删除、转换与预计新增输出及原因；只读，不承诺包含未参与转换的全部非音频文件；待生成文件明确标识；不得用最新扫描树冒充计划的冻结视图。

## 4 库存新鲜度与计划有效性分开判断

- 进入当前文件页时刷新该成员目录，完成前禁止修改；提供手动刷新。刷新失败保留旧视图并明确标注未刷新。
- 磁盘操作完成后刷新受影响的库存、概览统计与树缓存。
- 文件已修改但刷新失败时，分别报告「已修改」与「刷新失败」，不回报整体未执行，也不继续信任旧树。
- 计划是否失效由各 Task 的输入事实决定：转换按音频指纹判断，音频路径等输入变化要求重新规划；整理图片、文本或空目录不强制重做转换。重叠库根不能继续显示为已确认的新库存，执行前仍保留扫描与输入校验。

## 5 删除媒体库与其记录

- 删除媒体库条目需确认，并连同其处理记录、计划与执行结果一起在同一事务中删除，不留孤立记录；磁盘媒体与 `Delete/` 回收目录不动。
- 有活动任务（生成或执行）时拒绝删除；操作未注册类型时同样拒绝。
- 存在处理记录时可以改名，不能更换库根：根变更会让成员的相对路径全部失绑，因此该动作与文件管理占用同一准入槽位（0002）。
- 只有库行在删除路径之外消失时才会出现孤立记录：它只读，界面显示「媒体库已删除」，不能保存、生成或执行。

## 6 界面承载与状态归属

- 工作台自己的历史不是链：每个页面声明固定父级，返回目标由路由明确决定，不依赖历史猜测；旧长地址不再重定向（0003）。
- 详情与编辑是同一记录的载体，按容器宽度选择承载：宽屏相邻面板、中档模态侧栏、窄屏整页下钻。布局变化保留 URL、选择与编辑内容，同一时刻只挂载一个交互表单。
- Vue Query 拥有服务端/缓存状态（操作作用域键、变更与生成事件后的显式刷新）；选择、搜索词、冻结的批量列表与未应用编辑保持瞬时；扫描、生成、执行的 SSE 生命周期是瞬时进程状态，各自留在自己的 store，不当作可缓存资源。
- 返回列表保留勾选、筛选与滚动位置；刷新浏览器不恢复临时勾选；切换媒体库清空原库的临时选择。未应用的转换编辑沿用离开保护。
- 过期保存保留编辑并要求显式重新加载或放弃，绝不自动覆盖重试。

## 替代方案权衡

- 拒绝「命名工作集 + 永久历史」：浏览与整理都要先创建工作集，历史管理带来的复杂度大于价值；改为一条当前记录加一份当前计划。
- 拒绝「只隐藏历史」：不能满足只保留最后一次记录的要求，也控制不了历史载荷增长。拒绝「删除所有快照」：当前计划的审阅、输入校验与执行仍需要冻结事实。
- 拒绝保留孤立工作集（旧模型的只读孤儿）：删除媒体库时一并删除记录，只有库行被外部改动才留下只读记录。
- 拒绝「执行只能覆盖完整计划」：用户常常只想重跑一部分文件夹；拒绝按序号或名称临时挑选成员，改为记录内的 `folder_paths`，且范围必须属于记录。
- 拒绝仅在转换内实现文件管理，也拒绝为未来任务预建计划框架：共用文件能力有两个实际调用方，计划语义仍由任务负责。
- 拒绝用 VACUUM 代替历史清理：它回收空闲空间，不决定保留哪些业务数据（保留与清理见 0008）。
- 拒绝把界面状态放进 URL 或放进服务端缓存：选择与搜索是页面的瞬时状态，只有各页明确支持的参数才进地址（0003）。
