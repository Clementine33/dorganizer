# 7. 以媒体库为工作台，只保留当前处理记录

Date: 2026-09-19

Status: Accepted; implemented.

当前工作集要求先从媒体库选择固定成员、创建独立集合，浏览文件又会离开工作台。我们决定让媒体库直接成为工作台入口，将固定成员集合降为一次操作的处理记录，并共用文件浏览与管理能力；每种操作只保留当前记录和当前计划，以减少导航与历史管理复杂度。

详细交互、路由、Interface 和验收以 [工作集工作台与共用文件树 Spec v1](../workset-workbench-spec.md) 为准。本 ADR 记录长期决定及其理由，不重复 spec，也不表示现有代码已经实现这些行为。

## Context

[ADR 0004](0004-independent-workset-operations.md) 将 Workset 定义为一个媒体库中的固定成员集合，允许多条 Workset 及持久历史版本。这个模型适合计划管理，但普通目录浏览、整理及未来其他任务都要先绕过“创建工作集”这一层。概览成员当前跳到 libraries 文件树，返回后也失去操作上下文。

用户希望先选择媒体库，再浏览、整理、选择需要处理的目录。转换仍需一个明确的成员范围、冻结计划及执行校验，但不需要管理多条命名集合和无限历史。目录整理还需要同时服务概览、转换及未来任务，不能作为转换专属能力实现。

## Decision

### 1. 媒体库拥有工作台，处理记录属于操作

产品入口暂时保留“工作集”名称，选择其中的媒体库直接进入同一个工作台。概览浏览全部直接子目录，包括空目录和仅含非音频文件的目录；库级回收目录不作为成员。

用户明确选择范围后才创建处理记录。每个 `(library_id, operation_type)` 最多保留一条当前记录，当前只有 conversion。转换会提示并跳过无音频目录。继续复用现有 workset 存储固定成员，不进行全仓库重命名；创建时只初始化所请求的操作。

浏览范围因此独立于处理范围。未来另一种操作可以有自己的当前记录和成员选择，不与转换互相替换，但本次不实现未来任务。

### 2. 原子替换当前记录，只保留当前计划

再次选择范围时明确确认替换。新记录创建成功才在同一事务中替换旧记录及其关联数据；失败保留旧记录。有排队或运行中的生成、执行时禁止替换。

记录内重新生成计划时保留上一份成功计划。新计划成功发布才清理被替代的计划、执行结果和明细；生成失败、取消或中断不删除原计划。UI 不提供历史计划入口，数据库也不永久保留这些历史载荷。

保留当前计划的不可变快照、草稿并发版本、输入有效性校验和每份计划最多执行一次的约束。简化的是历史保留，而不是执行安全。技术性幂等凭据可按保留期存在；重试不能恢复已替换记录、误替换更新记录或重复执行。

### 3. 共用当前文件管理，任务独立解释计划

概览与转换使用同一个文件夹模块：按媒体库和成员相对路径刷新库存、浏览和管理当前文件。转换入口先由稳定 member ID 解析目录；概览直接使用库相对路径。扫描时重建的 folder ID 不承担长期导航身份。

不同上下文保留各自路由和明确返回地址，树展示在工作台主区域。转换负责从冻结数据构建计划审阅，不把最新库存当作计划快照，也不让共用文件模块理解转换草稿或 revision。

[ADR 0005](0005-task-seam-and-opaque-payloads.md) 的 Task seam 与 opaque payload 原则继续适用。未来 rename 可以复用当前文件能力，其计划解释在需要时再实现，不预建通用计划框架。

### 4. 直接文件管理成为受控的另一条写入路径

在成员内部支持单项重命名、单项移动和批量软删除；不操作成员根、不跨成员移动、不覆盖目标。软删除沿用库级 `Delete/`，报告实际回收位置，恢复由用户通过系统文件管理器完成。

写入必须由后端验证目录范围、符号链接与目标冲突。批量删除遇错停止，报告成功、失败和未处理项，不自动回滚。传输结果不明时先刷新核实，不自动重试写操作。

这明确改变了“只有计划执行可以修改磁盘”的旧约束。直接文件管理不伪装为转换计划，但必须满足自己的路径保护、并发控制和结果反馈契约。

### 5. 手动文件管理采用全局准入互斥

任意扫描、排队或运行中的生成、执行存在时，拒绝手动文件管理；手动文件管理期间也拒绝启动这些任务。检查与登记在后端原子完成，操作后的库存刷新属于同一次受保护过程。

选择全局互斥是因为多个媒体库根可能重叠，现有精确根路径检查不足以保护通用文件写入。接受其他媒体库忙时暂时不能手动整理的代价，避免本期引入完整路径锁管理器。

此决定不重写原有任务彼此之间的并发策略，也不改变 [ADR 0006](0006-execution-encode-concurrency.md) 的会话内编码池、提交顺序及停止行为。

### 6. 库存新鲜度与计划有效性分开判断

进入当前文件页时刷新该成员目录，完成前禁用修改。写入后刷新受影响库存和页面；若文件已修改但刷新失败，必须分别报告两个事实，不能回报整体未执行或继续信任旧树。

计划是否失效由各 Task 的输入事实决定。转换继续按音频指纹判断：音频路径等输入变化要求重做计划；整理图片、文本或空目录不强制重做转换。重叠库根不能继续显示为已确认的新库存；执行前仍保留扫描与输入校验。

### 7. 新数据契约不迁移，也不自动重置旧数据库

本次用新数据库验证。遇到不兼容旧数据库时明确拒绝并提示使用新数据目录；不自动清空旧库或媒体。

删除媒体库条目需确认一并删除其处理记录、计划和执行结果，不保留孤立工作集；磁盘媒体及回收目录不动。存在处理记录时可改名称，不可更换库根。

## Superseded decisions

- ADR 0004 §2、§4、§5 中的多条独立工作集入口、永久 revision 历史、孤立工作集及旧导航模型，由本文对应决定取代；固定处理成员、冻结计划及任务执行校验继续保留。
- ADR 0004 §6 的“唯一磁盘写入路径”由受控文件管理能力扩展。
- ADR 0005 Consequences 中的旧数据库自动 reset 政策在本次新契约下由“拒绝不兼容数据库、使用新目录”取代，Task seam 不变。
- ADR 0006 的执行内部模型不变。

这些替代关系是目标设计的优先级，不是已完成迁移的声明。实施时同步更新领域词汇与 HTTP 契约；历史 ADR 保留原文。

## Consequences and rejected alternatives

- 用户无需命名和管理处理集合，但主动接受失去旧设置、旧计划及旧执行结果的代价。确认、事务和幂等校验是这个取舍的必要组成。
- 拒绝“只隐藏历史”：它不能满足仅保留最后一次记录的要求，也不能控制历史载荷增长。
- 不用 VACUUM 替代历史清理。它回收空闲空间，不决定保留哪些业务数据；本期不增加自动压缩机制。
- 拒绝“删除所有快照”：当前计划的审阅、输入校验及执行仍需要冻结事实。
- 拒绝仅在 conversion 内实现文件管理，也拒绝为未来任务预建框架。当前文件能力有两个实际调用方，任务计划语义仍由任务负责。
- 接受全局文件管理互斥带来的并发限制。只有实际使用证明该限制不可接受时，再评估路径级协调。
- 浏览与直接管理覆盖无音频目录，但转换仍以明确选择的音频输入工作，不顺带扩展根目录散落文件或成员根管理。
